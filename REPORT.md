# Отчёт по Homework 01

## Результат

Собран сервис предсказания цены подержанного автомобиля. Обучающий pipeline и API
используют один порядок 12 входных признаков; API сверяет свою Pydantic-схему с метаданными
артефакта при запуске. Это исключает незаметное расхождение данных между обучением и
инференсом.

Логирование реализовано в PostgreSQL: для каждого успешного `POST /v1/predict` сохраняются
`request_id`, время, версия модели, JSON-признаки, прогноз, latency и HTTP-код. Запись
выполняется в фоне и не влияет на ответ клиенту.

## Журнал проблем

| Проблема | Диагностика | Решение / статус |
| --- | --- | --- |
| Старое ядро Jupyter ссылалось на предыдущую виртуальную среду. | Ноутбук не открывался из-за несуществующего интерпретатора в kernelspec. | Пересоздано окружение проекта и выбрано ядро Python 3.11. |
| Активная `.venv` не совпадала с окружением, которое ожидает `uv`. | `uv` выводил предупреждение о `VIRTUAL_ENV` и игнорировал активное окружение. | Использован режим `--active`; импорт пакета подтвердил версию `0.1.0`. |
| В тестах есть два предупреждения deprecation из `starlette.testclient` и `anyio`. | Предупреждения приходят из зависимостей FastAPI/Starlette, не из кода проекта. | Не подавлялись: тесты завершились успешно, предупреждения сохранены на скриншоте. |
| Docker при первой загрузке официального образа PostgreSQL отвечал медленно. | Зависаний приложения не было: задержка наблюдалась до старта контейнера, на внешней загрузке образа. | Повторный запуск использует Docker-кэш; SQL-чекпоинт будет зафиксирован отдельным скриншотом. |
| PostgreSQL вывел предупреждение `collation version mismatch`. | База была создана с collation version `2.36`, а текущий образ предоставляет `2.41`; при этом запрос и запись прогноза завершились успешно. | Это предупреждение Docker-образа/сохранённого volume, не ошибка приложения. Для чистого учебного запуска достаточно пересоздать volume перед повторной инициализацией БД; существующие данные при этом будут удалены. |

## Что будет показано на защите

1. Артефакт содержит `pipeline` и `metadata`, а API не принимает лишние поля и возвращает
   `422` для неверного payload.
2. `/ready` подтверждает, что модель загрузилась; `/health` проверяет живость процесса.
3. В Compose и Kubernetes PostgreSQL готов до старта API, а Kubernetes использует startup,
   liveness и readiness probes.
4. Скриншоты из таблицы выше фиксируют реальные команды и экран k9s, а не перепечатанный
   вывод.
